# Epic 5 — Authentication & Per-User Data Implementation Plan

> **For agentic workers:** Execute task-by-task with checkboxes; run the full verification chain after each task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real accounts via Supabase Auth (email magic link + Google wired/config-later), with every deck, card, schedule, review, session, streak and take owned by exactly one user — split into Task 1 (backend & data) and Task 2 (sign-in UI).

**Architecture:** Server-only Supabase client (`@supabase/ssr` over `cookies()`); identity only from `getUserId()`/`requireUserId()`; enforcement in Drizzle repositories via required `userId` params + ownership joins; `proxy.ts` handles route protection + session refresh. No Supabase client or key in the browser.

**Tech Stack:** Next.js 16.3.5 (proxy.ts = middleware), `@supabase/supabase-js` + `@supabase/ssr`, Drizzle, bun test, Playwright.

## Decisions locked

- Route: `/sign-in` (DESIGN.md screens table); epic file updated from `/login`.
- Google OAuth: action + button wired now, credentials configured later (manual Google Cloud + Supabase setup).
- E2E: lean — two-user isolation proven by real-DB integration tests; E2E covers signed-out redirects, open-redirect rejection, and the existing study loop under a real session (password sign-in via dashboard-created `e2e@colyglot.test` user + env-gated test-signin route; no service-role key).
- Baseline commit of uncommitted redesign work first.

## Global Constraints

- `userId` comes only from the session cookie (`requireUserId()`) — never from forms/params/bodies.
- Every repository function takes required `userId`; foreign rows = `undefined`/`false` (indistinguishable from missing).
- No `NEXT_PUBLIC_` Supabase vars; `SUPABASE_URL`/`SUPABASE_ANON_KEY` server-only; grep `.next/static` before done.
- Zero `LOCAL_USER_ID` references at Task 1 completion.
- Keep donut pattern: `await connection()` inside Suspense; `requireUserId()` in content components, never in page shells.
- Existing E2E aria contracts (grade buttons, headings) must not change.
- Full chain green before done: `bun run lint && bun run typecheck && bun run test` + `bun run build` + `bun run test:e2e` (from `apps/web` for build/e2e).

## Manual prerequisites (user)

1. Supabase dashboard → Authentication → Sign In / Providers → Email: enable (magic links on).
2. Authentication → URL Configuration: Site URL `http://localhost:3000`; Redirect URLs: `http://localhost:3000/auth/callback` (+ production when known).
3. Project Settings → API: copy Project URL + anon key into `apps/web/.env` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`).
4. Authentication → Users → Add user: `e2e@colyglot.test` / dev password / Auto Confirm (one-time, for E2E).
5. Later, for Google: Google Cloud OAuth client → paste client id/secret into Supabase Google provider.
